# Recovery

## Two backups, two jobs

| What | Recovers | Needs Ark server? | Survives lost phone? |
| --- | --- | --- | --- |
| 12-word seed | Spendable balance (mailbox + chain scan), not history or in-progress exits | Yes, for off-chain VTXOs | Yes, if the user still has the words |
| Encrypted wallet database | Full wallet: history, VTXOs, in-progress exits | No | Only if a copy lives **off the phone** |

Second’s current docs: the mnemonic alone is a safety net, not a complete backup. https://second.tech/docs/backups.md

Keel will never describe the seed as “all you need.”

## Seed

- Generated by Bark `generateMnemonic`.
- Shown once at create time; selected words must be verified before backup is marked complete.
- Stored in Keystore/Keychain. Reveal requires authentication. No clipboard by default. Screenshot blocking where the OS allows it (and we say that it is not perfect).
- Never uploaded. Never used as a password. Backup encryption keys are derived with HKDF and domain separation (`keel-backup-v1`).

## Manual encrypted seed export (available since 0.2.0)

- From the phrase screen at create time, or later from **Settings → Export encrypted backup** (biometric-gated).
- User picks a passphrase (min 8 chars, never stored by Keel). Key derivation: PBKDF2-HMAC-SHA-256, 600,000 iterations, random 16-byte salt. Encryption: AES-256-GCM, random 12-byte nonce.
- File format `KEELBK01`: magic+version, salt, nonce, iteration count, ciphertext. Wrong passphrase or any tampering fails at the GCM tag check.
- Written via the Android Storage Access Framework picker, so the destination can be local storage **or any installed cloud provider (Google Drive, Dropbox, …)**. Keel never sees cloud credentials and requests no account permissions.
- Restore: **Restore → Open encrypted backup file**, enter passphrase, wallet is recreated and syncs from the Ark server.
- This protects the seed. Full database backup (history, in-progress exits) is the continuous backup below.

## Encrypted database backup (implemented in 0.5.0)

- **Continuous (on-device)**: after every successful mutating wallet operation (send, board, refresh, offboard, Lightning claim, exit start) Keel snapshots the Bark datadir and encrypts it with an Android Keystore AES-256-GCM key (non-exportable, no passphrase needed). Kept in `noBackupFilesDir/autobackup/`, newest 3 generations retained. Restore: **Settings → Restore from local auto-backup**.
- **Manual (off-device)**: **Settings → Export full wallet backup** writes a passphrase-encrypted `KEELDB01` file via SAF (local storage, Drive, Dropbox, …). Payload = recovery phrase + zip of the wallet datadir. Restores with **no Ark server cooperation**.
- Snapshot: SQLite `VACUUM INTO` (API 29+; WAL checkpoint + idle-copy on older). Never `cp` a live `db.sqlite`.
- Envelope: plaintext manifest JSON (schema, network, wallet fingerprint, monotonic generation, time, Bark/app versions, SHA-256 of the snapshot) + `BackupCrypto` AES-256-GCM ciphertext. The manifest is readable before decryption so rollback/network/fingerprint checks run before any state is touched.
- Rollback: refuse to install generation *N* over a live wallet with generation *> N* (monotonic counter persisted per fingerprint). Backups for a different fingerprint are refused while a wallet exists; wrong-network backups are refused.
- Remaining destinations not yet wired: SAF folder auto-sync, optional Google Drive / iCloud. Manual export covers them today.

## Restore scenarios we must test

1. Fresh device, seed only, Ark server available → balance comes back; history may not.
2. Fresh device, seed only, Ark server down → honest failure; do not pretend the wallet is complete.
3. Fresh device, seed + encrypted DB → full restore including in-progress exit if the backup contained it.
4. Older backup vs newer live wallet → blocked with an explanation.

## Emergency exits

An in-progress exit lives in the database. Seed-only restore can lose it. Claim still depends on wallet data until the user claims to a normal on-chain address. See [ark-security-model.md](ark-security-model.md).
